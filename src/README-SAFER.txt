ПРОСМОТР ПЛАНА

После распаковки всего ZIP отдельная точка входа — View-Plan.cmd.
Она показывает общий план и оставляет окно открытым. Для отдельного способа:

  View-Plan.cmd HWID
  View-Plan.cmd Ohook
  View-Plan.cmd TSforge
  View-Plan.cmd KMS

Также общий CMD и четыре отдельных активатора принимают первым аргументом
/Plan, затем необязательное имя All, HWID, Ohook, TSforge или KMS. Например:

  MAS\All-In-One-Version-KL\MAS_AIO.cmd /Plan
  MAS\All-In-One-Version-KL\MAS_AIO.cmd /Plan TSforge

В отдельном активаторе /Plan без имени выбирает соответствующий способ.
В других пяти вспомогательных CMD этот параметр не добавлен: используйте
отдельный View-Plan.cmd или общий MAS_AIO.cmd.

Перехват /Plan расположен перед обычной инициализацией MAS: до запроса UAC,
смены QuickEdit, создания временных файлов, диагностики и вызовов активации.
Если /Plan обнаружен среди смешанных аргументов активации, такой запуск
отклоняется; продолжения в активацию нет. Дополнительные аргументы после
необязательного имени способа также отклоняются. Возврат из просмотра —
exit /b, а не переход в основное меню. Неверное имя способа даёт ошибку.

План читает ограниченный набор значений реестра Windows/Office C2R,
архитектуру процесса, свободное место на системном томе и настройки исходника.
Значения реестра используются как данные; исходник активации не импортируется.
Выводятся условные этапы, возможные затрагиваемые файлы и границы отката.
Нет остановки/запуска служб, licensing API, записи реестра, загрузок,
создания журнала, проверки подписи с возможными сетевыми запросами
или пробной записи для проверки прав. Вывод идёт только в консоль.
Системное журналирование запуска процессов самой Windows этим не управляется.

План не является разрешением на выполнение и не доказывает совместимость.
Точные MSI/UWP-конфигурации Office, эффективные права записи/удаления,
формат хранилища, создание бэкапов, сеть и результат активации в нём
помечены как непроверенные. Наличие свободного места не означает, что
его достаточно для конкретной операции. Показанные пути хранилищ — кандидаты.

ЖУРНАЛ ВОССТАНВЛЕНИЯ

Во время отдельно запрошенного обычного запуска журнал создаётся автоматически.
При текущей разработке этот код не запускался и журналов Windows не создавалось.

Основные журналы и журналы файловых операций TSforge:
  %windir%\MAS-Safer-Recovery\<идентификатор>\events.jsonl

Журнал конкретной файловой операции Ohook, manifest и резервные копии DLL:
  %windir%\MAS-Safer-Backups\<идентификатор>\events.jsonl
  %windir%\MAS-Safer-Backups\<идентификатор>\manifest.json

Резервные/временные файлы TSforge остаются рядом с соответствующим
хранилищем (.mas-safer-<идентификатор>.bak/.tmp/.restore и др.). Точные пути
записаны в журнале. Каталоги журналов ограничены SYSTEM и Administrators;
родительские каталоги проверяются на перенаправление через reparse points.

JSONL — один JSON-объект на строку. Поля:
  schema — версия формата;
  utc — время UTC;
  operation — идентификатор этой операции;
  parent — идентификатор основной операции, если он есть;
  scope — HWID/Ohook/TSforge/KMS либо конкретная файловая операция;
  event — этап;
  item, backup, auxiliary — затронутый путь, бэкап и временный путь/ссылка;
  sha256 — контрольная сумма, когда она известна;
  result — ограниченный статус или тип исключения.

Полные ключи, содержимое лицензий, installation/confirmation IDs, командная
строка и тексты исключений в events.jsonl не записываются. Пути могут
содержать названия пользовательских каталогов. Бэкапы — настоящие копии
затронутых файлов и могут содержать лицензионные данные; не публикуйте их.
Существующий консольный вывод MAS не превращён в обезличенный журнал.

Как читать события:
  operation-started / *-may-run / *-intent — намерение, не результат;
  backup-verified / backup-recorded — сведения о резервной копии;
  output-staged — подготовлен выходной файл;
  replace-returned / mutation-returned — файловая операция вернулась;
  files-committed — группа файлов применена, активация не подтверждена;
  rollback-intent / recovery-staged — начато восстановление;
  rollback-item — восстановлен/не изменён отдельный объект либо требуется
                  ручной разбор;
  file-rollback-ended — итог попытки ФАЙЛОВОГО отката;
  worker-ended — завершился обработчик TSforge;
  control-returned — управление вернулось в основной завершающий обработчик,
                     а не подтверждение активации;
  cleanup-retained — временный файл оставлен для разбора.

Отсутствие завершающего события, обрыв JSON-строки или предупреждение
о неполном журнале означают неизвестный результат. Не считайте это успехом.
При manual-recovery-required сохраните журнал, manifest и резервные файлы
для разбора. В этой ревизии нет кнопки или команды автоматического
восстановления всей Windows из журнала.

ГРАНИЦЫ ПОКРЫТИЯ

Основной журнал начинается перед диагностикой выбранного активатора
(или перед процедурой удаления Ohook/KMS). Более ранняя общая инициализация
MAS не протоколируется полностью. Основные фазы HWID/KMS/Ohook/TSforge
отмечаются, но каждый вызов реестра/службы/сети отдельно не протоколируется.
Некоторые ранние выходы оставят запись без control-returned; это намеренно
не выдаётся за успешное завершение.

Подробные резервные пути, контрольные суммы и пофайловый откат покрывают
Ohook и запись хранилищ TSforge. Прежний порядок PKEY2005-проверок,
генерация ключей, содержимое DLL и протоколы активации в ревизии 3
не изменялись. Внесена обёртка обработки непредвиденной ошибки TSforge,
которая возвращает код ошибки 3 вместо неявного продолжения.

До очередной файловой мутации запись намерения обязательна: её отказ
прерывает следующий шаг и запускает существующий откат уже затронутых файлов.
Запись событий во время отката и после успешной мутации выполняется без
прерывания восстановления при ошибке самого журнала, включая закрытую консоль.
События CMD сохраняют входной errorlevel для существующих вызывающих веток.

Файловый откат НЕ возвращает прежние ключи через licensing API, реестр,
состояние служб, планировщика или результат удалённой активации. Сбой диска,
питания или конкурирующее изменение состояния может потребовать ручного
восстановления. Журнал уменьшает неопределённость, но не делает операции
единой транзакцией и не устраняет ограничения ревизии 2.

СОВМЕСТИМОСТЬ

Новые план и PowerShell-журнал требуют Windows PowerShell 5.1.
Поскольку основной журнал обязателен, на более старом PowerShell основная
фаза активатора откажется продолжать. Совместимость с ним не заявляется.
Это дополнительное ограничение ревизии 3. Точная работа ACL, JSONL,
CMD/PowerShell/C# и активации на Windows в этой ревизии не испытана.
