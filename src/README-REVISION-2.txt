СТАТУС

Исправления второй ревизии внесены и проверены статически. Тесты,
компиляция, запуск CMD/PowerShell, активация, работа с Windows и службами

Статический разбор не подтверждает работоспособность активации Windows/Office.
Полного отката состояния лицензирования, всех метаданных NTFS или изменений
при аварийном отключении питания здесь нет.

Оригинал сохранён отдельно в Microsoft-Activation-Scripts.zip, без изменений.
Предыдущий экспериментальный ZIP также оставлен отдельно без изменений.
Новая версия: Microsoft-Activation-Scripts-safer-experimental-r2.zip.

ИСПРАВЛЕНИЯ РЕВИЗИИ 2

1. Ohook: ошибка подготовки больше не приводит к удалению исходной DLL.
   Все новые DLL подготавливаются и сверяются до первой замены. Список
   попыток изменения пополняется непосредственно перед файловой операцией,
   а не до подготовки временного файла. При откате уже совпадающая с резервной
   копией DLL остаётся на месте. Для восстановления сначала готовится и
   проверяется отдельный файл; затем выполняется Replace или Move.
   Прежнего удаления существующей DLL перед копированием резервной нет.
   Новые файлы и ссылки удаляются при откате только при совпадении с тем,
   что планировала создать текущая операция. Неизвестные объекты сохраняются.

2. TSforge: учитывается частичный отказ внутри File.Replace.
   До замен создаются отдельные проверенные .bak и все временные выходные
   файлы. Счётчик попыток обновляется перед вызовом native API. При исключении
   проверяется и текущий файл, а не только успешно завершившиеся операции.
   Если оригинал уже перемещён и путь назначения отсутствует, восстановление
   допускает отсутствующий конечный файл, проверяет родительские каталоги
   и использует Move подготовленной копии. Существующий файл восстанавливается
   через Replace. На ошибках резервные и временные файлы сохраняются.
   Для файлов восстановления копируется DACL; не запрашивается назначение
   чужого владельца временным файлам. Это не полная копия всех метаданных NTFS.

   Основание: Windows документирует частичное выполнение ReplaceFileW,
   в частности ERROR_UNABLE_TO_MOVE_REPLACEMENT_2 (1177):
   https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew
   Работа с DACL использует API .NET Framework:
   https://learn.microsoft.com/en-us/dotnet/api/system.io.fileinfo.getaccesscontrol?view=netframework-4.8.1

3. PKEY2005: новые проверки формата выполняются до удаления ключей.
   До UninstallProductKey/UninstallAllProductKeys выполняется предварительное
   открытие physical/token stores и чтение используемых metadata entries.
   Эти объекты закрываются без Commit, то есть без сохранения изменений.
   После предварительной проверки выполняется восстановление службы.
   После штатных licensing API хранилища открываются заново: старая копия
   из предварительной проверки не записывается поверх обновлённого состояния.
   Запись ProductId/DigitalProductId и удаление cache.dat перенесены после
   успешного файлового batch.Commit, до обращения за обновлением к службе.
   Ветка PKEY2009 сохраняет прежний порядок удаления и установки ключа.

   Ограничение: предварительная проверка не блокирует состояние Windows
   на всё время операции. Ошибка ввода-вывода или изменение хранилища после
   неё всё ещё могут произойти после удаления ключей. Файловый откат не
   восстанавливает прежние ключи через licensing API и не откатывает реестр.
   Обещания «любая ошибка оставляет прежнюю активацию» эта версия не даёт.

4. Ohook OSPP uninstall: удаляется распознанная ссылка в каталоге Office,
   даже если рядом отсутствует sppc.dll. Проверяются точная цель ссылки,
   известный хеш общего OSPPC.DLL и подпись исходной DLL. Ссылки удаляются
   до удаления их общих целей; обратный порядок отката сначала восстанавливает
   цели. Каталоги нормализуются перед удалением дубликатов, в том числе
   устраняется различие из-за завершающего разделителя пути.

5. Диагностика: пропущенный ремонт не считается успешным или неудачным
   по старому errorlevel. Команды включения служб и классификация результата
   выполняются только при разрешённом ремонте; иначе выводится Skipped.
   Для отсутствующего token folder явно указывается пропуск создания.
   Ошибка переустановки лицензий не берётся из старого errorlevel при пропуске.
   SkipRearm не меняет реестр и не останавливает службу при запрещённом
   ремонте; при разрешённом ремонте сообщение зависит от результата команды.
   Не добавлена общая CMD-группа вокруг вывода списков служб: значения
   процентовыми подстановками читаются после цикла, как в исходном варианте.

6. Ohook: отказ helper/preflight прекращает дальнейший сценарий.
   Код возврата helper сохраняется отдельным флагом и проверяется в двух
   C2R-ветках и после каждого вызова MSI. MSI возвращается из подпрограммы
   с ошибкой вместо перехода в общий финальный обработчик внутри вызова.
   После отказа не выполняются следующие MSI-ветки, общая очистка ключей
   и другие заключительные операции. Уже выполненные до отказа изменения
   лицензирования не объявляются отменёнными файловым откатом.

ПОВТОРНАЯ СТАТИЧЕСКАЯ ПРОВЕРКА

Просмотрены diff ревизия 1 -> ревизия 2, ветви нормального завершения,
подготовки, частичного отказа ReplaceFile, отката, OSPP uninstall,
возврата из MSI и диагностические условия CMD.

Сверкой текста подтверждено:
- C# в общем CMD и отдельном TSforge совпадает с verification/PatchedFull.cs;
- оба встроенных Ohook helper совпадают с hardening/patches/OhookSafety.ps1;
- встроенный StoreWriteBatch совпадает с отдельным исходником помощника;
- сохранены 11 явных Commit в существовавших ветках записи;
- два новых preflight using не вызывают Commit;
- сохранены CRLF во всех распространяемых CMD;
- в ревизии 2 изменены общий CMD и четыре отдельных активатора;
  остальные пять CMD совпадают с первой ревизией;
- SHA-256 оригинального и предыдущего экспериментального ZIP не изменились.

Алгоритмы генерации ключей, криптографические константы, DLL-полезная нагрузка
и сетевые протоколы в ревизии 2 не изменялись. Исправления затрагивают
подготовку/сохранение/откат, порядок проверок и обработку ошибок.
По повторному чтению перечисленные дефекты управления исправлены;
это не результат исполнения и не доказательство отсутствия других ошибок.
Синтаксис новых CMD/PowerShell/C# не проверялся их интерпретатором/компилятором.
Синтаксис Python-файлов генератора разобран как текст без выполнения генератора.

СОХРАНЁННЫЕ ОГРАНИЧЕНИЯ ПЕРВОЙ РЕВИЗИИ

По умолчанию запрещены публичные KMS, автоматическое продление KMS,
автоматическая смена редакции HWID/KMS и общая очистка пользовательских
лицензий Office. Автоматическая смена региона не выполняется.
Некоторые ремонты реестра/служб отключены. Smart App Control не отключается;
при соответствующем состоянии Ohook прекращается. Неизвестные DLL не
заменяются. Новому помощнику Ohook нужен Windows PowerShell 5.1.
Строгий parser token store не проверен на реальных Windows-хранилищах.
Эти ограничения могут прекращать сценарии, которые оригинал продолжает.
